Tealc: the lab's own agent

Tealc is our in-house AI agent. It runs locally on Claude plus LangGraph, keeps persistent memory across sessions, and has its hands on the lab's email, calendar, drive, and research tools. Today it functions as an administrative assistant that can also do real literature work. The next version is a postdoc. The long arc, which is what this page used to be called, is a lead investigator that can carry an evolutionary-biology project from question to manuscript with optional human judgment at the critical checkpoints.

What Tealc does today

The current Tealc is reactive. It works when Heath opens a chat window and asks it to do something. That is still useful, because a single conversation now routinely spans lab email, calendar, drive, and the primary literature without a human stitching those sources together by hand.

Administrative assistant Email, calendar, drive, files, notes Reads, drafts, remembers. Sends nothing.

Tealc reads Gmail with keyword filters, checks the day's calendar, searches Google Drive by content, opens Google Docs, and reads local files like manuscripts, grant drafts, or data. It can draft reply emails, but drafts always sit in Gmail waiting for a human to approve and send. It keeps a notes table in SQLite that survives across sessions and laptops, so a decision made on Monday is still remembered on Friday.

This tier is most of what an administrative assistant does, done in seconds, with total recall.

Literature scout PubMed, bioRxiv, OpenAlex, citation tracking Finds the papers, pulls the citations, summarizes.

The research tools are Europe PMC for full-text literature, bioRxiv for preprints, and OpenAlex for broad search with citation counts and open-access links. A separate citation tracker pulls who is citing the lab's own work. Tealc can also load the full llms-full.txt corpus, so it starts every conversation knowing the lab's research program, active projects, and student roster in detail.

Memory Persistent across sessions and machines SQLite checkpoints, Google Drive sync.

Every conversation is checkpointed to SQLite. Notes are a separate table that Tealc can write, list, read, and delete. The whole stack, including the database and the OAuth tokens, lives inside a Google Drive folder, which means a new laptop is three commands away from a fully restored agent with every prior conversation and note intact.

The gap we are closing: reactive to always-on

The honest limitation of today's Tealc is that nothing happens at 2 a.m. There is no morning briefing, no background monitoring, no email that says "a paper that cites your 2014 work was posted overnight and here is why it matters." Closing that gap is the current build target.

Phase 2 A scheduler, a briefing, and a 90-day grant radar APScheduler, launchd, and a briefings table Chainlit reads on open.

A second Python process sharing the same SQLite database runs on a schedule. Every morning it assembles new citations to the lab's work, recent preprints in chromosome and sex-chromosome evolution, flagged emails, the day's calendar, and a countdown of the nearest grant deadlines. When Heath opens the chat, Tealc opens with "here is what I found while you were away" instead of waiting for a prompt. Mac launchd keeps the process alive across reboots.

The postdoc we are building toward

A postdoc is a researcher who can read a draft and give a structured critique, run an analysis in R, write a first pass of a manuscript section, suggest three journals and argue for one, and draft a response to reviewers. Tealc will not hit that bar in a single release. It will hit it one tool and one workflow at a time.

Phase 3 Code execution and document write-back R and Python sandboxes, Google Docs and Sheets read and write.

Today Tealc reads data. Next it runs analyses. R execution lets it run comparative-methods code, read the output, and interpret results. Python execution lets it parse data files and run everything that is not already in an R package. Google Docs and Sheets write-back lets it drop a figure caption or a paragraph directly into a manuscript, and read the karyotype databases and CURE data the lab maintains in Sheets. Full-text fetch from arXiv and bioRxiv lets it work from complete papers instead of abstracts.

Phase 4 Manuscript and grant machine Structured critique, journal targeting, response to reviewers.

Given a full draft manuscript, Tealc produces a structured critique: argument flow, methods gaps, framing for the target journal, and the reviews we should expect. Given a grant call and a pile of prior successful grants, it helps structure specific aims, significance, and innovation. Given a manuscript plus reviews, it drafts a point-by-point response. The pattern is always the same: Tealc writes the first pass, a human supplies judgment.

Phase 5 Student and lab management Milestone tracker, recommendation letters, lab-meeting agenda.

Every student in the lab has a timeline of chapters, committee meetings, fellowship deadlines, and job-market milestones. Today that lives in a PI's head and on a few scattered documents. Tealc gets a student milestone database, flags who is behind, drafts recommendation letters from a student's CV and Heath's notes, and builds lab-meeting agendas from recent progress notes. An alumni tracker keeps an eye on the careers of people who have left the lab, because how alumni do is one of the real measures of a lab.

The long arc: lead investigator

The original name of this page was "lead investigator," because the eventual ambition is an agent that can take a research question, design a comparative analysis, pull the data, run the phylogenetic models, interpret the results, and produce a draft manuscript, with human review at the important checkpoints. That is still the north star. It sits at the end of the roadmap because it depends on everything in front of it: code execution, document write-back, persistent project memory, and domain-validation logic that notices when an answer is biologically impossible.

We are not trying to build a robot principal investigator. We are trying to learn, one phase at a time, what shape of agent is actually useful to a working scientist, and where today's models break down on the specific kind of work evolutionary biology asks for.

Researchers supply the questions, the skepticism, and the judgment. Tealc handles search, extraction, computation, and first drafts. The goal is not a robot PI. It is the most capable postdoc imaginable.

Design principles

  • Draft-only on email. Tealc never sends. A human approves every message.
  • Service protection. Every incoming ask gets evaluated against the goals of the lab. Requests that would grow service load without advancing the science get a polite decline drafted automatically.
  • Triage mode. When the day is already overloaded, Tealc asks for the single most important thing first instead of offering a menu.
  • Persistent memory. Every conversation and note survives restarts and new laptops.
  • Audit trail. Every tool call is visible in the Chainlit step display. Nothing Tealc does is hidden from the human it works with.
  • AI amplifies effort, humans supply judgment. The lab's own AI philosophy, applied here.

Where this is likely to break

If a Claude-powered agent could already run a complete evolutionary-biology project unassisted, someone would have shipped it. Instead, we expect specific failure modes, and we are instrumenting the agent to surface them.

  • Hypothesis selection under uncertainty. Agents are trained to complete tasks. Research is not a task. We expect Tealc to drift toward hypotheses that are easy to test with the data in front of it, rather than hypotheses most likely to be true.
  • Biological plausibility. Computing a statistic is easy. Noticing that the statistic describes something biologically impossible is the test. We want to see whether Tealc flags it or publishes the number anyway.
  • Novel-result discipline. Agents are trained to be confident. Evolutionary biology asks researchers to be precise about which part of a result is actually new. This is where the seams will show most in a first-draft manuscript.
  • Scope discipline. A graduate student learns, painfully, when a project is done. An agent without explicit structure does not. Watching where the scope escapes is probably the single most informative signal.

How to follow along

Every prompt, every response, and every generated artifact is logged. Tealc's current live work is visible on the live console: a status indicator and a feed of the most recent tool calls, refreshed every thirty seconds. When the build reaches a publishable milestone, a companion manuscript will describe the methodology and the agent's behavior, intended as a case study for anyone else thinking about putting an agent on a real research problem.
