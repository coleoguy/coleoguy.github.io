Editorial rules
- Write for a sharp undergraduate. Use direct, accurate prose, define necessary jargon, and use no em dashes. Nothing addresses Heath personally or says an author is known to the lab. Do not fill missing facts with guesses.
- Never repeat a paper or story from any previous slot, even if its URL differs. Normalize DOI links, compare titles and identify syndicated copies. Never repeat a history subject. Do not repeat the lead topic of either of the two previous issues, judged by subject rather than merely wording the label differently.
- Feature: find a recent evolutionary biology paper, initially from the last three days, using PubMed, publisher pages, bioRxiv and public scholarly sources. Prefer followed authors or Texas A&M affiliations when names and affiliations really match, then topic fit and variety. Treat preprints explicitly as preprints. Confirm title, author order, publication date and DOI against publisher or primary metadata. Open and read the abstract and accessible paper. Describe only what the source supports; if only the abstract is accessible, record that limitation in source_audit and avoid unsupported numerical or methodological claims.
- Write a short declarative lead headline and one-sentence deck, two paragraphs totaling 170-210 words, and a Where to push box of 45-60 words. The box is a clearly proposed question, limitation or follow-up, not a claim that an experiment has already been performed. Research each author's public institutional, lab, ORCID or personal professional page and write about 50 words. State current role, institution and training only when verified; omit unknown details.
- Slot 2: CLASSIC on Tuesday and Saturday, otherwise BEYOND. CLASSIC is a landmark evolution/genetics paper, with what it showed, how, why it matters and a sentence about what followed. BEYOND is a recent biology paper outside ecology and evolution, usually from the last three days. Write a headline, linked citation and 85-110 words. Confirm the paper's real publication date, distinguishing online publication from a future print issue date.
- Slot 3: HISTORY every Friday. Otherwise SCIENCE, unless a genuinely significant academia item occurred in the last week and none of the preceding six issues was ACADEMIA. SCIENCE is a result outside biology from the last week, 85-110 words. HISTORY is a reliable, balanced account of a deceased scientist or historical episode, 100-130 words; avoid negative claims about living people. ACADEMIA is science-policy, funding, higher-education or publishing news, 70-90 words plus a why field of 30-45 words, never Friday. Every story has a headline, linked citation and primary source URL. Distinguish a demonstrated result from a projected future capability.
- Set tomorrow to the following day's normal slot 2 and slot 3 labels. Do not predict a discretionary ACADEMIA substitution.
- If no suitable source meets freshness rules, broaden the search before giving up. Do not quietly label an older paper as new. If a useful issue cannot be supported within the rules, report a missed issue and leave the last good issue online.

Source audit and validation
- Add source_audit as a JSON array. Each entry has url, title, used_for and evidence. used_for is exactly one string from lead, person_1, person_2, slot2, slot3; cover all five at least once. Evidence is a brief note of facts actually checked in that source, including access limitations. Use public professional sources only. The audit is public with the issue, so it must contain no private config, account information or personal context.
- Resolve every DOI or confirm it in authoritative metadata; inspect links and compare important claims to the actual sources. Check names, dates, word counts, structure, weekday choices, repeats and allowed HTML. If cloud code execution is available, use a temporary cloud workspace to run the repository's validator against the candidate and existing records, without AI API calls. Fix candidate errors; never weaken the validator to make a draft pass. The GitHub publisher performs the final deterministic check.
